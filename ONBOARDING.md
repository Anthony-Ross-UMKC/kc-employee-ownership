# How we're working — read this first

How this project is set up, and how to get going. Nobody has to write code or type commands
to work on this — that is deliberate, and it applies to all of us.

## What we're building

A website for Kansas City business owners on employee ownership as a succession option:
plain-language information about how it works, plus a questionnaire an owner can fill out to
get a read on whether their company is a plausible fit and what problems it would run into.

Not a paper. The site is the deliverable.

## How the work is split

We each write our own sections so we're never editing the same thing at the same time.

| Person  | Writes                                            |

Confirm these before starting — it's a proposal, not settled.

The homepage and the site's styling are shared. Say something to the group before changing
either.

## Nobody should do the same work twice

This is the thing most likely to waste someone's week, so it's worth understanding.

While you're working, your changes are private to your copy — nobody else can see them until
you say your section is ready. That's good, because half-finished pages don't go live. But it
means **the only way the rest of us know what you're doing is the task list.**

You don't have to maintain it. Claude does. When you start something it marks it as yours
immediately, and when you sit down it tells you what everyone else is working on. Just don't
work in silence for a week — say what you're picking up, and it handles the rest.

If you want to know where things stand, ask: *"What's everyone working on?"*

## Setting up

The setup is the only fiddly part. Once you're through it you never touch it again.

1. Make a free account at **github.com** if you don't have one, and send Anthony the username
   you chose.
2. Wait for an email inviting you to the project, and accept it.
3. Install **Git** from git-scm.com. Accept every default. You'll never use it directly —
   Claude needs it installed to do the work for you.
4. Install **Claude Code**, open it, and tell it:

   > Clone https://github.com/Anthony-Ross-UMKC/kc-employee-ownership and set me up to work
   > on it. My name is [your name].

5. The first time it saves anything, a browser window will ask you to sign in to GitHub. Use
   the account from step 1 — **not** any other GitHub account you might have. Getting this
   wrong is the most common way this goes sideways, and it cost Anthony an hour.

If any of it fights you, stop and text the group rather than clicking through. It takes five
minutes with someone else looking and an hour alone.

## Working

Open Claude Code in the project folder and say what you want to work on. That's the whole
process.

Things you can just say:

> What's everyone working on?

> I want to add a section on vesting to my page.

> Is this wording okay, or does it sound like legal advice?

> Give me a source to check.

> I'm done for today.

> My section is ready for the team.

That last one puts your work on the live site. Everything before it stays private to your
copy.

**The live site:** https://anthony-ross-umkc.github.io/kc-employee-ownership/

## Two rules that matter more than the rest

**Nothing on this site tells a reader what to do.** We inform; we do not advise.
Unauthorized practice of law is a real constraint on this project, not a technicality. If
something you write starts to sound like advice to a particular business, flag it — or just
ask Claude whether it crosses the line. It's been told to refuse to publish anything that
does.

**Every fact needs a source.** Every number, dollar figure, and legal statement has to be
traceable to a primary source. Do not reuse the figures from the project brief — none of
them have been verified, and under the syllabus each of us is personally responsible for
every number we publish.

Checking sources is deliberately broken into small pieces. If you have ten minutes, say
*"give me a source to check"* and you'll get exactly one.

## One thing to be careful about

This project is public — anyone on the internet can read it. That's fine for our own writing.
It is not fine for readings, articles, or PDFs we didn't write. Don't add those; cite them
instead. Redistributing someone else's copyrighted work is a bad look on a law school
project.

## If something goes wrong

Tell Claude what happened and let it fix it. If it can't, tell Anthony. Nothing is ever
lost — that's the entire point of how this is set up. Don't try to fix it by deleting things.
